# v2.9 最短に近い経路と滑らかな自由移動

基準main：`0015f93af4c8b46b019c2dc0cff285ea03bff493`（v2.8、PR #29のマージ）。作業ブランチ：`feature/v29-smooth-navigation`。mainへのマージ・本番公開は行わない。

## 調査した既存構造

`pathfinding.ts` は4近傍A*で、移動先をセル中心へ戻していた。`movement.ts` の `advance` は既に連続座標・距離正規化・中継点をまたぐ移動予算を持つ。`approachPoint` は4隣接候補を経路の点数で比較していた。敵は同じ経路APIを使用し、目的地セルの変更を再計算の条件としていた。

`map-runtime.ts`、`map-view.ts`、`enemy-symbols.ts`、`navigation.ts`、`active-map.ts`、`types.ts`、衝突・接近・セーブ・関連テストを確認した。既存の移動・描画・敵状態・イベント・戦闘復帰エンジンを維持し、新しい探索エンジンは追加しない。

## 経路と衝突

- 開通した直線は、現在の実座標からタップした実座標へ直接進む。始点・終点をセル中心に吸着させない。
- 障害物がある場合は8方向A*。直交1、斜め√2、始点からグリッドへの接続は実距離を使う。対角の両側のセルが開いていない角抜けは禁止。
- 優先キューは最小ヒープ、ヒューリスティックはoctile距離。半タイル以下の半径では、中心間の隣接辺は両側セルの開通によって安全を保証できる。大きい半径と実座標の接続には区間の衝突検査を使用する。
- 復元した経路にstring pullingを適用し、半径を含めて安全な最も遠い中継点まで直線化する。これは厳密な連続空間の最短経路を保証するものではなく、安全な近似最短経路である。
- `clearSegment` は線分と障害タイル矩形の交差・最短距離を解析的に調べる。疎な点のサンプリングだけに頼らず、移動区間全体のswept circleを検証する。マップ境界も半径を含めて検査する。
- 壁・水・境界内に半径が収まらないタップは、既存の「歩ける地面を選んでください」の案内で拒否する。無理にセル中心へ補正しない。

## 移動・接近・敵

主人公の速度は130ワールドpx/秒を維持する。斜め移動も距離で正規化し、角で余った移動距離を次の区間へ引き継ぐ。4〜120fpsと不均一なフレーム間隔で同じ移動距離を検証する。バックグラウンド復帰の大きな時間差は従来どおり250msまでに制限する。4方向の向き・既存SD表示を維持する。

移動中の再タップは現在位置から計算し直す。移動処理自体も次の区間を検証し、古い・不正な経路を通らない。

接近先は従来の4隣接候補を維持し、実際の経路長の合計で比較する。直線距離の下限で不要な探索を省く。対象との間に壁がある候補や、対象内部の停止位置は使わない。接近だけではイベントを開始しない。相互作用の視線も解析的に検査し、旧4pxサンプル間にある壁の角越しの会話を禁止する。

回帰ケースでは、点数3の341.02px経路より、点数4の298.39px経路を選択する。既存の巡回・追跡・帰還は新しい経路を使い、敵自身の衝突半径を渡す。主人公だけが立てる壁際では、敵の半径でも安全で元の接触範囲内にあるセル中心を追跡先に使い、追跡の停止を防ぐ。同一セル内で動く主人公も再追跡できる。速度・索敵範囲・追跡距離・リーシュ・接触半径・戦闘復帰条件の数値は変更しない。

## 動的な通行制限

Runtimeはグリッド内容を監視し、変更時に主人公の経路を再計算し、敵の経路を破棄する。`updateMap` は同じID・寸法・タイルの更新だけを受け付け、勝手に位置を変えない。到達不能なら停止する。移動の各区間にも衝突検査がある。

会話・装置の終了時には、既存の位相などの変化に加えて有効グリッドの変化を検出し、既存のマップ再表示・安全な復帰を使う。目的地案内のキャッシュもグリッド内容を比較し、配列を直接更新した場合に古い案内を返さない。砂嵐・時流などの既存イベント条件や `activeMap` の判定はそのまま利用する。

## データと保存

保存キー `astra-chronica:v1`、schema `version:2` を維持し、移行フィールドを追加しない。経路・目的地・探索用キャッシュはRuntime内だけに保持する。再読込時は保存位置から新しい操作の経路を計算する。

v2.8の検証済み成果物と、全161マップ、全18章、会話選択、依頼、時流装置、道標、武器、90ノードと系統、敵編成の定義が一致することを照合した。戦闘方式・計算・敵能力値・報酬・成長・装備・スキル・所持品・エンディングを変更しない。`save.ts`、`battle.ts`、`progression.ts`、`equipment.ts`、`src/data` は変更しない。

## 検証と再現方法

- 新規単体182件。全161マップの全対象への経路と、敵の各半径・巡回経路を区間・中間点で検証する。直線、同一セル内の回避、角抜け、丸い角の正しい余裕、経路長、速度、再タップ、接近、敵AI、地形変更、目的地キャッシュ、保存互換も確認する。
- 旧移動系33件を保持。古い中継点の個数・最後の向きの期待は、回避距離と到達・衝突・新しい実際の向きで検証するよう更新した。テスト削除・skip・期限の延長は行わない。
- Chromiumの実タッチで320/390/430pxを検証。グリッド刻みの旧テストドライバーで細分化せず、一度のタップ後の斜め軌跡、正確な到達点、無効なタップ、移動中の再タップ、イベント非自動起動、位置保存・再読込を観測する。仮想時計を固定して操作待ち時間による測定誤差を避ける。スクリーンショット3枚と生の軌跡を保存する。
- 最終一括検証は `npm test`（46ファイル・3,126件）、`npm run build`、既存86件を含むブラウザ87ファイル。全161マップ×4幅の644表示ケース、実WebGL、新規データから全18章の通しプレイ（109戦・452イベント・18回再読込）を含む。
- `.github/workflows/smooth-navigation-v29-validation.yml` は検証専用。26グループに全87ファイルを重複・欠落なく割り当て、各ジョブ内は1ブラウザだけで実行する。全27ワーカーのHEAD・ソース・ビルドとログのハッシュを検査し、すべて成功した場合だけ `v29-verified-final-evidence` を生成する。Pagesの公開設定は変更しない。
- CIの集約結果は成果物内の `docs/test-results/v29-ci.json`、生ログは `docs/test-results/v29-ci/`。通しプレイのイベント記録・表示ケース・実タッチ軌跡・スクリーンショットを同梱する。確定した全件結果は、成功後に作成するPRにも記載する。

ローカルでは単体46ファイル・3,126件すべて、新規181件と旧移動系33件の計214件の重点検証、スマホ3幅の実タッチ、本番ビルドが成功。初回の隣接辺の検査と探索の負荷は、ヒープ・中心間の安全性・候補の下限距離による枝刈りで改善した。全件の確定結果は上記CIで記録し、成功前に完了扱いにしない。
