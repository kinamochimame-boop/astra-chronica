# v4.0 星詠みの冒険コンパス

基準main：`7f4dff75fa236838c61574e543a76e6a7338d46f`。作業ブランチ：`feature/v40-adventure-compass`。mainへのマージ・公開は行わない。

## 実装と判定

ホームの先頭に、章番号・章名・現在地・次のメイン目的・イベント完了数を表示する。詳細を展開すると目的地、次の操作、既存出口案内を確認できる。直後に「冒険を再開」、3人のレベル・現在武器・残SP、依頼の状況を表示する。既存の冒険・章選択・育成・記録・単独戦闘・保存なし検証などの入口は残す。

`compassChapter` は解放済みの選択章、保存マップの章、開始済み章の順に採用する。未解放の選択章は採用しない。メイン目的は既存 `mainObjective`、進捗数は実イベントIDの完了情報から導出する。能力値やSPを追加保存・二重計算しない。

探索では既存の目的パネル・経路・地図を維持し、閉じたコンパス詳細と追跡中の依頼の短い案内を追加する。探索メニューからコンパス画面へ移動し、探索へ戻れる。装備・星脈・依頼・手帳の既存復帰経路も維持する。画面を開き直すと最新の進行から表示を再生成し、探索中の詳細は既存目的更新時に更新する。

## 依頼追跡

受注済み・未受取の依頼1件だけ追跡できる。解除可能。`questAvailable`、`questReady`、`questClaimReason` により「未受注／進行中／目標達成／報告可能／報酬受取済み」を分ける。解放前の依頼名を新しい一覧へ出さない。受取後は追跡を解除する。

任意フィールド `trackedQuestId?: string` のみ追加。通常ロードでは未知ID・未受注・受取済み・未解放IDを除外する。追跡変更は既存 `growthTransaction` を再利用し、保存失敗で元へ戻す。

案内は既存ナビゲーションへ任意の目的地を渡し、同じ出口・通行・経路・対象接近判定を再利用する。メインと依頼のキャッシュを分ける。調査対象は既存 `objectRevealed` を確認する。未解放の地点名、隠れた対象、未知のマップ構造を表示しない。経路がない場合は装置・解放条件の確認を案内し、ルートを捏造しない。メインのミニマップ経路は依頼追跡で置き換えない。
