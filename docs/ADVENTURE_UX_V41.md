# v4.1 冒険UI・画面復帰の改善

## 基準と調査

開始時にorigin/mainをfetchし、`94a35a14284801ae9911ce2ef0780a1271dbac97`を確認。`feature/v41-adventure-ux`で作業する。README、package、main、v4.0のダッシュボード／コンパス／バックアップ、探索HUD／ナビ／ミニマップ、依頼、保存、育成・ビルド、v2.9／v3.8／v3.9／v4.0の設計書と関連CSS・テストを確認した。

既存の進行判定・経路・成長計算・保存処理を再利用し、src/data、戦闘／ATB／EP／CT／AI／成長／装備の数値定義は変更しない。新しい探索エンジン、保存フィールド、能力値キャッシュは追加しない。

## 修正前に再現した問題

- 320/375/390/430px・高さ844pxで、ホームが縦に長く、装備入口が約1,736〜1,768px下にあった。仲間の名前とレベルが二重表示され、冒険開始も2つの主ボタンになっていた。
- 探索の詳細を開くとcanvasが181〜205px押し下げられた。v3.8の地図は固定されていたが、v4.0のコンパス詳細には通常フローの高さ変化が残っていた。
- 探索→装備→戻るで、装備画面下部のスクロールが残り、探索の見出しへフォーカスしても画面外だった。
- 依頼画面の戻るハンドラーを保持し、探索→ホーム→単発戦闘へ進んでから実行すると戦闘を中断できた。旧画面のイベントが現在の共有contentを操作できた。

修正前の撮影と生計測は `docs/screenshots/v41/before-*` に保存。アプリのソースSHA256は `bdbcef2a373410d7bacedfbfaf60aaaea0c93b7839ff2326ddef9d5abfd1b63b`。新機能の実装前に実行し、後から同名の仮データで置き換えていない。

## 変更

### ホーム

コンパスと冒険再開を先頭に置き、3人のレベル・武器・残SPの直下へ装備／星脈／既存ビルドの入口を配置。追跡依頼があれば優先表示する。記録・章選択・バックアップは「冒険・記録と設定」、単発戦闘や保存なし検証などは「補助操作」へまとめた。既存の全入口は残している。仮SDと戦績は「仲間と戦績」で確認でき、通常表示で名前・レベルを重複させない。追加の開閉を強制しない2列メニューとし、主要ボタンは44px以上。

### 探索HUD

通常は短い目的と既存の経路案内を表示し、詳しい情報は絶対配置のパネルで確認する。元の詳細文・地形状態・依頼案内は保持する。詳細の開閉はcanvasを動かさず、既存pause／stop／save／resumeを使用する。詳細を読んでいる間は歩行入力を受けず、Escapeでも閉じられる。DOMの開閉リスナーは画面破棄時に解除する。

装備・星脈・依頼への直接ボタンを追加。メニュー内の同一機能と名前を区別し、重複した操作対象を避ける。地図・経路ON/OFF、安全候補、再タップ、キャンセル、敵接触は変更しない。メインの経路を依頼で置き換えず、未知の地形や対象を新しく公開しない。canvasの高さ・ワールド座標・衝突・移動速度は変更していない。

### 復帰とフォーカス

`ViewSession`で画面世代とDOMの接続状態を確認し、古い画面の戻る・操作を無効化する。探索やホームを離れた時のスクロールは一時オブジェクトに保持し、同じ画面・マップへ戻る場合だけ復元する。依頼の地点を意図的に変えた場合は新しい地点を優先する。遅れて到着する復元処理も世代チェックを行う。

前進時は新しい画面の先頭と見出しへ、復帰時は元の位置と操作ボタンへ戻す。深いスクロールでscrollY169・見出しY=-62.25pxになるケースを追加再現し、元の操作ボタンを優先してフォーカスするようにした。育成画面の相互切替でも起点を維持。依頼の戻る表示も「ホームへ戻る／探索へ戻る」を明示する。ビルド入口は既存の管理パネルを開き、新規のビルド処理を作らない。戦闘結果のserial・報酬確定・中断復旧は変更していない。

## 保存・数値互換

保存キー `astra-chronica:v1`・version:2と、game／formatVersion:1／createdAt／progressのバックアップ形式を維持。save／save-backup、safePose、world、survey、builds、trackedQuestId、依頼・選択・装備・経験値・SP・戦績は変更しない。既存growthTransactionの失敗時ロールバックを利用する。2MiB、深さ・危険キー・ノード数・配列数の上限、上書き前保護、読戻し検証を緩めない。
