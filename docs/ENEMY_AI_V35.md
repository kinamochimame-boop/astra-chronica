## 判断順序と設定

1. 生存者のみ候補にする。
2. 生存している挑発者がいれば最優先。対象選択用の追加乱数を使わない。
3. 次の設定に応じて対象を選ぶ。
4. 決定後に既存のかばう・ガード・バリア・属性・ダメージ・状態異常処理をそのまま適用する。

| 分類 | 条件・動作 |
|---|---|
| A 標準 | 従来のランダム選択。未設定のIDも同じフォールバック |
| B 攻撃 | 負傷者がいる場合、60%で最低HP割合の対象、40%で生存者からランダム |
| C 防御 | HP35%以下で30%の確率で既存のdefendを選択。直前の判断行動が防御なら選択しない |
| D 妨害 | 今回の攻撃に実際に設定された状態異常のうち、未付与の種類数が最大の生存者を優先 |
| E 保護する既存AI | enemyPatternを持つ敵は新AIを一切適用しない。ボスだけでなく、通常敵の固定チャージ・反撃も従来のまま |

60%と30%はv3.5の暫定値であり、恒久的なバランス仕様ではない。
攻撃型で最低HP対象が1人・生存者が3人の場合、ランダム分も含む実際の狙われる確率は約73.3%。残り2人はそれぞれ約13.3%。
全快時は従来の1回のランダム選択を維持する。最低HP割合が同率なら元の候補順を維持して注入乱数で選ぶ。
挑発がなく生存者が1人だけの場合も、従来同様に1回だけ乱数を消費し、不要な判断乱数で後続の会心・付与列を変えない。

防御は既存の被ダメージ50%軽減と、次の本人の行動機会で解除される仕様を使用する。
敵の通常CTを1回消費する。行動不能の機会には判断しない。固定防御・反撃・チャージを持つ敵は新防御の対象外。
判断履歴はBattleごとのEnemyTactics内に保持し、戦闘終了・撤退・破棄でクリア。再戦は新しいBattleで開始する。

妨害型は既存の物理attackStatuses、またはその行動で使う魔法のstatusesを参照する。
確率0の効果は対象評価に使わない。全員が同じ状態なら従来のランダムへ戻す。
効果の付与判定・確率・持続・解除を変更せず、全体攻撃も既存の生存者全員を対象とする。
すべての乱数はBattleの注入済みrandomを使用し、新たなMath.random呼び出しは追加しない。

## 比較方法

109戦闘×20固定乱数×2操作方針×旧新版＝8,720戦闘（4,360組）。
比較専用の固定育成条件を使い、プレイヤー能力値、装備、習得ノード、所持品、乱数seedを旧新版で同一にする。
レベルは章ごとにLv1、3、7、11…50。装備はそのイベントまでに得られる武器から既存のスコア規則で選ぶ。
ノードは既存の取得条件・SP制約で取得する。所持回復品は各3個。
これは実プレイのレベル経過を保証するモデルではない。実際の進行・成長・報酬は別途、新規データからの全18章ブラウザ通し検証で確認する。

- AUTOのみ：通常攻撃を自動実行し、回復・技・アイテムを使わない。
- 支援あり：HP割合を見て回復・回復品・挑発・ガードを使用し、アステルはEP範囲内で攻撃技を使う。
- 記録：勝敗、戦闘内秒数、直接・継続被ダメージ、戦闘不能回数、敵の防御回数、最終攻撃対象の分布。
- 安全ゲート：対象戦闘合計で勝率低下5ポイント以内、時間増15%以内、損害増20%以内、戦闘不能増0.05回/戦闘以内、時間切れ0。
- 個別遭遇ごとの値も記録し、各遭遇の勝利数が旧版を下回らないことも検証する。

## 残存リスク

60%/30%は今回の比較に基づく暫定値。固定乱数と操作モデルだけで全プレイヤーの体験を保証するものではない。
無回復AUTOでは戦闘不能が増える場合がある。支援行動、挑発・かばうを含めて検証し、個別戦闘の差を公開する。
iPhone Safari実機は未確認。Chromiumのモバイルタッチと既存UIの回帰検証を使用する。
既存Phaserチャンクサイズ警告は継続。mainへのマージ・本番公開は実施しない。
