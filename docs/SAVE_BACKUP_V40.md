# v4.0 セーブデータ管理

## 操作

ホームの「セーブデータ管理」から容量効率のよいコンパクトJSONを書き出し、別端末でファイル選択・プレビュー・明示確認を経て読み込む。自動同期、ネットワーク送信、サーバー保存、個人情報収集は追加しない。

書き出し前に既存の保存処理を実行する。失敗したら書き出しを中止し、未保存であることを警告する。成功後も端末上のファイル保存を断定せず、ダウンロード先の確認を案内する。通常のdownload属性とBlob URLを使用し、対応ブラウザではファイル共有も利用できる。非対応なら書き出しへ案内する。Blob URLは短い待機後に解放する。

ファイルは `astra-chronica-save-YYYYMMDDHHMM.json`（UTC）とし、次の外側だけを追加する。進行内部のversion:2は維持する。

```json
{"game":"astra-chronica","formatVersion":1,"createdAt":"ISO 8601日時","progress":{"version":2}}
```

上記は形式説明用の省略例であり、実ファイルにはparty・equipment・adventure・skillTree・consumables・quests・choicesなどの全必須項目が必要。

## 厳密検証

`parseBackup` と `validateProgress` は通常起動の `load` と責務を分ける。壊れた入力をfreshへ置き換えて受理しない。

- ファイル選択時とUTF-8本文の両方で上限2MiB。JSONを解析する前に本文サイズを検査する。
- 最大深さ24、走査ノードは全マップの総セル数×2＋50,000（現在254,616）、文字列長200,000。非有限・安全域外の数値を拒否する。配列は実マップ最大セル数（最低1,024）、オブジェクトは1,024項目で、走査スタックへ展開する前に制限する。
- `__proto__`、`prototype`、`constructor` を全階層で拒否する。
- ゲーム識別子・バックアップ形式・作成日時・version:2・必須フィールド・3人のレベル／経験値・戦績を検証する。
- 既存の章、装備、ノード、回復品、依頼、選択、ビルド、探索履歴の正規化を再利用する。ただし入力からデータが欠落・改変される場合は拒否する。集合型の文字列／数値配列は順序違いを許し、ビルド枠などオブジェクト配列の順序は維持する。
- 探索マップ、解放条件、座標範囲、向き、対象ID、イベント／戦闘復帰情報を検証する。検証後のsafePose・中断戦闘復旧は既存ロードと同じ。壁内など安全でない位置は既存の安全入口へ戻ることがある。
- UIはtextContentを使用し、入力をHTMLとして挿入しない。ファイル読み込み例外、連続選択の世代管理、画面離脱後の非同期結果を処理する。

スキーマ2の過去セーブに任意のbuilds・survey・trackedQuestIdがなくても読み込める。通常起動時のv1ロード互換は変更しない。バックアップ機能のファイル形式は上記ラッパー＋version:2であり、古い生のlocalStorage JSONを直接ファイル入力する機能ではない。

## 上書き保護

プレビューには検証後の日時・章・戦績・3人のレベルと上書き警告を表示する。確認前／取消／検証失敗ではStorageを変更しない。

確認後は、現在の保存文字列を補助キー `astra-chronica:before-import:v1` へ1世代保護し、読戻し一致を確認してから元キーを置き換える。元キーへのlocalStorage単一書込はブラウザ標準の原子性を利用する。書込後は文字列一致と構造を再検証する。失敗時は元の文字列へ戻し、成功として画面を再初期化しない。保存先自体が書込・巻き戻しとも拒否する異常時は、保護データを残し、再読込せず退避するよう警告する。

成功時だけ稼働中の進行を置き換え、既存タイマー・探索を終了し、選択章を再導出してホームを再生成する。古いメモリ状態を自動保存して読み込み内容を上書きしない。「前回読み込み前のデータを確認」で保護した1世代を再プレビューできる（表示日時は今回の確認日時と明示）。補助キーのために空き容量が必要で、容量不足では元データを維持して読み込みを拒否する。

前版v3.9の新規通し試験で実測した全18章・109勝の進行データも事前に検証し、初期の整形JSONで442,501バイト（修正後はコンパクトJSON）・18章・最終章クリア保持を確認した。これは前版データの互換試験であり、v4.0の通常通し試験とは区別する。v4.0の通常通し試験にも、全章後の実UI書出し・プレビュー・取消・全主要項目保持を追加している。

## 最大探索履歴の回帰修正

全161マップ・102,308セルの履歴を持つ進行を検証したところ、初期案の走査上限150,000が正規データを拒否した。固定上限を、全マップの2種類の履歴＋構造余裕から導く254,616へ変更した。ファイル上限2MiBは維持し、空白で容量を増やさないコンパクトJSONへ変更した。161マップすべてのseenと通行可能セルのwalkedを保存・復元する自動テストを追加した。ゲーム進行・履歴の内容は削減しない。

修正後の実測：前版の全18章・109勝データへ161マップすべてのseenと通行可能セルのwalkedを設定した履歴上限fixtureは724,671バイト。書出し・読込後も161マップ・109勝・最終章クリアを保持した。これは容量・互換性用fixtureであり通常プレイとは報告しない。
