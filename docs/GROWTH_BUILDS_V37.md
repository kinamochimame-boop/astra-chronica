# v3.7 育成ビルド管理・無料振り直し

## 基準と実装範囲

最新mainをfetchし、指定コミット `a6a85dcf3596ecb2e0c487449e179c511f93fda4` と一致を確認した。
作業ブランチは `feature/v37-growth-builds`。mainへのマージ・本番公開は行わない。

各主人公に3枠ずつ、合計9枠の育成ビルドを追加した。構成は名前・習得ノードID配列・装備武器ID（装備なしはnull）。
未保存を区別するsavedと、破損した構成の再適用を防ぐinvalidを補助項目として持つ。
能力値・SP残高・アイテム数量・経験値をビルドに保存/複製しない。

## 操作

ホームまたは探索メニューから既存の「スキルツリー」「装備」を開く。両画面に同じビルド管理パネルを配置した。

1. キャラクターを選択する。
2. 「ビルド管理・比較・振り直し」を開き、1〜3の枠を選択する。
3. 名前は入力後「名前を保存」。初期名はビルド1/2/3。現在の構成は「現在の構成を保存」。上書き時は確認する。
4. 「現在の構成と比較」で、武器・ノード数・使用SP・主要能力・特殊効果を確認する。
5. 「このビルドを適用」で、武器と全ノードを一括置換して保存する。
6. 「スキルを振り直す（無料）」は対象名と返却SPを確認して実行する。やめる/ESCでは変更しない。

名前はNFC正規化後24 Unicodeコードポイントまで。制御文字・不可視の書式制御文字・山括弧を除去し、空なら初期名に戻す。
絵文字のサロゲートペアを切断せず、名前はtextContent/valueで表示する。HTMLとして挿入しない。
新しいUIは仮表示で、横スクロールを要求しない。主要ボタンは44px以上。確認はネイティブdialogでキーボード/スクリーンリーダーにも対応する。

## 適用の検証・一括性

`growth-builds.ts` に名前正規化、保存/改名/適用/振り直し、能力内訳を分離した。
`GrowthContext.inBattle`はすべての変更APIで必須。main.tsは現在のscreenを読むコールバックを渡す。
画面から戦闘中の管理導線を提供せず、古いDOMの適用ハンドラーが残ってもライブの戦闘状態で拒否する。

適用前に、枠番号、保存状態、不正フラグ、ノードIDの実在/所有キャラ/重複、必要Lv、前提ノード、総SP予算、現在の武器所持数と適性を検証する。
`normalizeHeroNodes`/`totalSP`/`equipReason`を再利用。SP予算は**未使用SPではなく現在レベルの総SP**で検証する。現在のノードを置き換えるため、使用済みSPも新構成の予算へ戻る。
全検証後、選択キャラのskillTreeとequipment.equippedだけを同期的に更新する。装備入手APIは呼ばず、数量を増減させない。
適用できない場合は理由を表示し、どちらのフィールドも変更しない。

UI変更はgrowthTransactionを経由する。保存成功時だけ成功メッセージを出し、保存失敗/例外時は元の進行データへロールバックする。
元はbuilds未設定だった場合は、その任意フィールドも削除して元どおりに戻す。

## 無料振り直し

選択した1人の習得ノードを空配列にする。残りSPは既存の `2 × (レベル−1) − 現在の習得コスト合計` から導出されるため、使用分が全額戻る。
SP残高の別カウンターを加算しない。繰返し操作でSPを増殖できない。
レベル/経験値、他の2人のノード、武器/所持品、保存済みビルド、章進行/依頼/選択履歴は維持する。
振り直し後も保存済みビルドはそのまま。再適用時に現在の条件で再検証する。

## 能力表示と戦闘への反映

Battleと同じ `cloneUnit → growUnit → equippedUnit → withSkillTree` を使う。
装備分は装備適用後−成長後、ツリー分はツリー適用後−装備適用後。新しいダメージ式やUI専用の能力式は追加しない。
弓装備限定の速度、最大HP依存のツリー防御も既存のwithSkillTreeを経由するため内訳に反映する。

- 現在Lv・総SP・使用SP・残りSP、現在武器
- 最大HP/MP・攻撃・防御・速度の、成長済み基礎/装備/ツリー/合計
- 特殊効果の既存説明、現在武器/実効SPDでの通常攻撃CT（1倍速・一時補正なし）
- 保存ビルドとの能力差・武器・ノード数・コスト・特殊効果
- 習得可能な選択ノードについて、習得前後の主要能力差

適用不可の保存ビルドは理由を表示し、不正なノードを落とした能力を有効な構成であるかのように表示しない。
条件付き効果は説明文で条件を示す。戦闘中の一時補正/低HP条件などを、恒久的な基本能力として上乗せしない。
新しい戦闘は現在のID構成から能力を再計算し、開始済みBattleのコピーは書き換えない。

## セーブ互換性

キー `astra-chronica:v1`、schema `version:2` を維持。新しいbuildsフィールドは任意。
古いセーブに存在しない場合は、読み取り時に3枠の安全な既定値を供給する。保存操作前はfieldそのものを追加しないため、既存の保存形状も維持する。
新しく保存したデータはロード時に3人×3枠に正規化する。4枠以上は採用しない。

ロード時の扱い：

- 名前は正規化し、未知のキーや能力値/数量などの余分なフィールドを採用しない。
- 既知だが現在は高レベル/未所持のビルドは保存しておき、適用時に不足理由を表示する。レベル到達/武器再入手後は再検証できる。
- 未知/別キャラ/重複ノード、未知/別キャラ武器は不正フラグを付ける。不正IDは保存し直さず、有効な部分だけを勝手に適用することもない。
- 不正フラグは再読み込み後も残し、現在の正常な構成で上書きすれば解消する。
- buildsの破損で既存のparty/equipment/skillTree/adventure/world等を初期化しない。

旧版から読み込んだ後の再保存/再読込、実際の第1/9/18章の旧セーブを検証する。旧版クライアントは追加項目を知らないため、旧版へ戻って再保存した場合のビルド枠保持までは保証しない。
