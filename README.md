# アストラクロニカ 〜星詠みの遺した約束〜

Vite + TypeScript + Phaser 3による、日本語・縦画面の3人パーティRPGの最小プロトタイプです。有料サービスや外部画像・Webフォントへの依存はありません。

## 起動

Node.js 22.12以降を推奨します。

```sh
npm install
npm run dev
```

表示されたURLをPCブラウザで開きます。同一LANのiPhoneから試す場合は、開発PCのLAN IPとポート（例 `http://192.168.1.10:5173`）を使用してください。

```sh
npm test           # 戦闘・セーブの自動テスト
npm run build      # 型検査と本番ビルド（dist/）
npm run preview    # ビルド結果の確認
```

ブラウザ操作テストは、別ターミナルで `npm run dev` を起動したうえで `npm run test:browser` を実行してください。Chromiumが必要です（既定 `/usr/bin/chromium`、`CHROMIUM_PATH` で変更可能）。タイトルから勝利、撤退による敗北、保存復元、320/390/1280px幅を確認します。iPhone実機テストの代替にはなりません。

## 基本操作と実装範囲

1. タイトルからホームへ進み、「戦闘開始」で霧の森へ向かいます。
2. ラウンドごとに生存する味方・敵を素早さの降順に並べます。同速なら味方の登録順、敵の登録順で決めます。現在の行動者と次の6行動を表示します。
3. 味方の行動時はコマンドを選び、敵（攻撃）または味方（ヒール・かばう）のカードをタップして対象を選択し、「○○を実行」で確定します。敵は自動行動します。
4. HP 0のユニットは順番から除外され、攻撃・回復の対象にできません。敵全滅で勝利、味方全滅で敗北です。撤退も敗北として記録します。
5. ホーム・再戦を利用できます。戦闘開始時にHP・MPは全回復し、防御・かばうは解除されます。

|キャラクター|コマンド|MP|効果|
|---|---|---:|---|
|全員|通常攻撃|0|単体攻撃|
|全員|防御|0|次の自分の行動開始まで被ダメージ50%軽減|
|アステル|強撃|6|通常攻撃の2倍の威力|
|リナ|ガード|3|次の自分の行動開始まで被ダメージ75%軽減|
|リナ|かばう|4|生存する味方1人への攻撃を肩代わりし35%軽減、次の自分の行動開始まで|
|メイ|ファイア|7|単体魔法攻撃、基本威力72|
|メイ|ヒール|8|生存する味方1人のHPを85回復、最大HPまで|

MP不足ではスキルを選択できません。HP満タンへのヒール、戦闘不能者へのヒール、自己かばうはできません。無効な操作ではMP・ターンを消費しません。かばう使用者が戦闘不能になると肩代わりしません。敵の攻撃対象は生存者からランダムに選びます。攻撃・魔法は12%で1.5倍クリティカルになります（回復はクリティカルなし）。

演出中は操作をロックし、撤退時にはタイマーを取り消して再戦への持ち越しを防ぎます。小さな移動・明滅、ダメージ／回復／クリティカル表示、直近のログと最大100行の履歴、勝敗画面の演出があります。動きを減らすOS設定にも対応します。

通常戦闘はスキルを使っておよそ6〜10ラウンド、操作・判断時間を含め1〜3分を目標にした数値です。実際の所要時間は操作速度に左右され、実機での計測は未実施です。固定seed100戦の自動シミュレーションで、強撃・ファイア・必要時のヒールを使う戦略が95%以上勝利し、12ラウンド以内で勝利することを検証しています。

アステル（戦士）、リナ（タンク）、メイ（魔法攻撃）の役割は固定です。「編成」は閲覧用の仮画面で、武器切り替え、ジョブ・転職、蘇生は未実装です。物語は導入と戦闘後の短文のみです。正式キャラクター画像・音声はありません。

localStorageの `astra-chronica:v1` に開始状態・戦闘回数・勝利回数・各人のレベルと経験値を保存します。内容のschema versionは2で、旧version 1の戦績は読み込み時に引き継ぎます。リロードするとタイトルから再開し、戦闘途中の状態は保存しません。保存拒否・破損データでも起動でき、保存不可時は画面に通知します。ブラウザのデータ消去で進行も削除されます。

## 構成・画像の差し替え

- `src/battle.ts`：表示から独立した行動順・スキル解決
- `src/data/`：味方・敵・スキル・状態異常定義
- `src/types.ts` / `src/effects.ts`：型・属性相性・状態異常・能力補正
- `src/progression.ts`：経験値・レベル上限・能力成長
- `src/lab.ts`：保存しない手動検証モード
- `src/balance.ts`：威力・回復量・軽減率・クリティカル確率・演出時間の調整値
- `src/save.ts`：バージョン付き進行保存
- `src/main.ts`：日本語DOM UI、画面遷移、戦闘操作
- `src/visuals.ts`：Phaserによる背景・2頭身SD図形
- `src/style.css`：青と金の縦画面レイアウト、タッチボタン、safe area対応

正式画像を `public/assets/` に置き、`Stage.preload()` を追加して `this.load.image('astel', import.meta.env.BASE_URL + 'assets/astel.png')` のように読み込み、対象Unitの `texture` にキーを設定してください。キーが未設定、または画像が読み込まれていない場合は図形で表示されます。UIはDOMボタンでキーボード操作にも対応します。

## GitHub Pages

相対ベースパス設定済みで、`dist/` は任意の静的ホスティングに配置できます。GitHubの Settings → Pages → Source を **GitHub Actions** に設定してください。付属ワークフローはmainへのpushでテスト・ビルド後にPagesへデプロイします。PRではテストとビルドのみ実施します。第1弾は公開・iPhone Safariでの勝利画面までの確認済みです。第2弾までのmainを引き継いでいます。第3弾も公開設定を変更せず、レビュー用PRを作成してmainへのマージを待ちます。

iPhone実機での検証は別途必要です。音声、正式画像、装備変更、戦闘中断セーブは未実装です。

## 公開作業とiPhoneでの確認

1. 第3弾のfeature/battle-foundation-v3 → mainのPull Requestをレビューし、テスト・ビルド成功を確認してマージします。
2. リポジトリの Settings → Pages → Build and deployment → Source で **GitHub Actions** を選択します。
3. Actions → Validate and deploy Pages を開きます。mainの実行がなければ Run workflow → Branch: main → Run workflow を選びます。
4. build・deployが両方成功し、Settings → Pages に公開先が表示されることを確認します。承認待ちの場合はActionsの Review deployments で github-pages を承認します。
5. Pages画面の Visit site を開いて動作確認し、そのURLをiPhoneのSafariで開きます。

リポジトリを非公開にして運用する場合、非公開リポジトリからPagesを利用するには対応するGitHubプランが必要です。Pages画面でプラン制限が表示された場合は、対応プランを利用するか、所有者がソースコード公開の可否を判断して公開リポジトリに変更する必要があります。リポジトリの公開範囲は自動変更しません。Pagesの公開サイトはソースリポジトリとは別に一般公開される場合があります。

iPhoneでは縦画面で「ゲーム開始」→「戦闘開始」→行動者を確認→コマンド・対象をタップ→「○○を実行」を繰り返して勝利画面まで確認してください。下の操作ボタンが見えない場合は縦にスクロールできます。ホームに戻りページを再読み込みし、勝利数が保持されることも確認してください。撤退すると敗北画面を確認できます。

本番ビルドでタッチ操作を再検証する場合は `npm run build` → `npm run preview` の後、別ターミナルで `BASE_URL=http://localhost:4173 npm run test:browser` を実行します。自動テストはタッチ対応Chromiumでの確認で、iPhone実機Safariの検証は含みません。

## 第2弾のiPhone Safari確認項目（PRマージ・デプロイ後）

- 既存の勝利回数が残り、タイトル・ホーム・編成を開けること。
- 現在の行動者・次の順番が表示され、敵が自動で行動すること。
- 強撃・ファイアでMPが減り、MP不足のスキルが押せないこと。通常攻撃・防御で続行できること。
- リナのガードで被ダメージが減り、かばうで選択した味方への攻撃を肩代わりすること（敵の対象はランダムなので複数回確認）。
- メイのヒールで選んだ生存者が最大HPを超えず回復し、戦闘不能者は選べないこと。
- ダメージ・回復・クリティカル表示、HP/MP、戦闘ログが読めること。
- 小さい縦画面でも下部の味方情報・コマンド・実行ボタンをタップでき、横にはみ出さないこと。
- 演出中の連打、撤退→すぐ再戦、タブの切り替え後でも進行が止まらず、行動が重複しないこと。
- 勝利・敗北後にホームへ戻れ、再読み込み後も戦闘回数・勝利回数が保持されること。

## 第3弾：戦闘内部基盤

毒・麻痺・睡眠・暗闇・沈黙・火傷・凍結、7属性、攻撃/防御/素早さのバフ・デバフ、勝利時の経験値とレベル成長を追加しています。ファイアは火属性で25%の火傷付与、敵には火・水・光の相性例を設定しています。他の状態異常と能力補正は、ホームの **戦闘基盤テスト（保存なし）** で付与・解除・1行動ずつの進行を確認できます。

検証画面は本編の戦績・成長・保存には影響しません。状態異常・能力補正は本人の行動終了（スキップを含む）で持続が減り、素早さ補正は次ラウンドの順番から反映します。第1・第2弾のセーブは同じキーから読み込み、戦績を引き継ぎます。

[内部仕様・調整するファイル・自動テスト・iPhone確認手順](docs/BATTLE_FOUNDATION.md) を参照してください。第3弾のiPhone実機確認は未実施です。

## 戦闘基盤テスト v0.4

効果付与対象・生存敵のみの攻撃対象・回復/かばう対象を分離し、撃破時に攻撃対象を自動切替します。敵の攻撃停止、睡眠/凍結の自然解除と被攻撃解除の個別シナリオ、本人の行動機会の前後表示、確定順と素早さの比較、固定乱数、詳細検証ログを追加しています。本編のセーブには書き込みません。

[変更ファイル・維持した仕様・自動テスト・iPhone実機確認手順](docs/LAB_V04.md) を参照してください。`npm run test:lab` で新しいタッチ操作テストを実行できます。mainへのマージはユーザーレビュー後です。

## 第7弾：装備・武器切り替え v0.7
